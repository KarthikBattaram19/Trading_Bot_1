02 — Pipeline walkthrough

Where a candidate would flow, and where it stops

Seven stages in execution order, modelled from the code at c25caa5 rather than from docstrings. Every funnel count is absent — no cycle has ever run, locally or in production — so the useful reading is which stage would drop a candidate.

signals in —

GARCH(1,1) forecast from daily log returns and an intraday ATM IV z-score. MLE fitting is off, so fixed 0.05 / 0.05 / 0.90 weights are always used.

Drops on: <21 daily closes or a flat series → garch_distorted; <5 intraday IV samples → z-score unusable.

feature_assembly in —

Live Breeze enrichment capped at max_symbols = 15 inside a shared 90 s budget; daily closes fetched live per symbol; ATM IV appended to the session store; earnings calendar joined; all of it assembled into a QuantSnapshot with explicit usability flags.

Drops on: no live marks; budget exhaustion returning an empty series; any Breeze exception returning []. Where a corrupt IV store kills the cycle outright — on the first symbol with live marks.

F-1 iv_history corruption — local/CI blocker F-3 budget exhaustion looks like missing data F-4 vega ineligible first ~50 min F-7 earnings calendar is empty
strategy_selection in —

Three eligibility predicates, all requiring live marks plus usable spot and IV. A strategy publishes only at coverage ≥ 0.60 and eligible ≥ 6. Since scanned = 15 (the enrichment cap, not the 213-name universe), the real bar is 9 of 15. At the current max_symbols the ratio binds harder than the count — the two swap below max_symbols = 10, where the count of 6 would bind.

Drops on: STRATEGY_COVERAGE_ABORT — the strategy leaves available_strategies entirely.

F-5 min_eligible_symbols = 6 is inert at max_symbols 15
ranking_gating in —

Gate evaluation (options-only is hard-locked), weighted scoring, a failure-memory penalty, then calibration. No calibration artifact exists, so every recommendation is uncalibrated / heuristic. Survivors are filtered by the effective confidence floor and cut to the top 3.

Drops on: score ≤ 0; confidence < 0.70 (bootstrap floor while real closes = 0); rank outside the top 3.

F-6 the floor gates a score, not a probability
execution_gates in —

Fires only when SUPERVISION_MODE = fully_autonomous; every other value — including blank and typos — fails closed to "approval required". Production is already set to fully_autonomous. The one-trade lock is ledger-derived from learning_store.json, so it survives a restart. Then gates, the 2 % spread cap, and rank 1 → 2 → 3 fallback.

Drops on: supervision mode; one-trade lock; a failed gate; spread > 2 %.

F-8 supervision confirmed fully_autonomous in prod
fill in —

PaperEngine.submit_order is the sole fill source for the autonomous path — nearest-strike ATM CE, one lot, nearest expiry at DTE ≥ 10, expanded into the full structure by the structure builder. Holds no disk state: the ledger is in-memory and re-initialised on every boot.

Drops on: no resolvable ATM contract; PaperLedgerError; StaleMarksError.

feedback in —

close_position calls record_ledger_close, writing the realized outcome and releasing the one-trade lock. The recommend → approve → paper_sim → learning loop is genuinely closed in code; what is missing is any traffic through it.

Drops on: a position with no recommendation lineage; a seed fixture (excluded by design).

What to watch on Monday

  1. The Breeze session token. No token → no live marks → no GARCH → all three strategies abort. Nothing downstream matters. The largest external risk, and one I cannot verify ahead of the session.
  2. Coverage at the 9-of-15 bar. The most likely place a technically healthy production run still produces nothing.
  3. generations still 0 while ticks climbs, plus last_actions containing tick_error. This is the detection signal for "F-1 is on production after all". generations increments only after the awaited cycle returns, so a cycle that keeps dying leaves it pinned at 0 while ticks marches on — a divergence that is durable and cannot be overwritten.
    Do not use last_error, and do not reintroduce it. I originally recorded it as the tripwire and it does not work: _loop sets self._last_error = None after every successful tick, and with tick_sec = 30 against a 600 s cadence, 19 of 20 ticks are within_cadence skips that count as successes and wipe it. It reads null ~95 % of the entry window even when every generation is failing — and for the same reason the scheduler does not sit in degraded.
  4. Whether executed ever turns true, once generations does start climbing.
Largest funnel drop-off — unknown The funnel has never been instrumented with live traffic, in either environment. The drop-off is predicted at feature_assembly from the call chain, but predicting is not measuring, and this panel stays empty until a cycle actually completes.
